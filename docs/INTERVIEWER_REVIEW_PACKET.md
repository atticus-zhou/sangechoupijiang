# 面试官评审包说明

这份文件用于说明：当 `https://www.atticus.asia/three-stooges/` 还没有被 Vercel 刷新，或者面试现场网络不稳定时，应该如何安全、诚实地展示“三个臭皮匠”。

## 先说结论

当前公开评审包可以证明：

- 产品不是一张静态介绍页，而是有办公室、样例交付物、追溯文件、验收卡和发布门禁的多 Agent 工作台原型。
- AI 漫剧制片办公室已经把“故事 -> 资产 -> 提示词 -> 图片记录 -> Word 制片画布 -> 下游交接清单”整理成可复核链路。
- 无 Key 展示不会读取作者的 API Key、Cookie、`config.yaml`、本地工作区或真实用户产物。
- 公开样例只证明结构、流程和交付格式，不证明真实模型画质已经达到生产级。

当前公开评审包不能证明：

- 面试官可以直接在线消耗作者的模型额度。
- 飞瓜、豆包、千问、DeepSeek 或其他第三方平台已经在线打通。
- AI 漫剧真实图片质量已经通过真实模型和人工验收。
- 研究办公室已经具备飞瓜会员级全自动截图和数据采集能力。

## 5 分钟评审路线

1. 先打开公开展示首页，确认页面写明 no-key demo、固定样例和安全边界。
2. 下载 AI 漫剧 Word 制片画布，查看它是否能把故事、人物、道具、场景、镜头提示词和交付说明放在同一份文档里。
3. 打开 handoff manifest，确认每个交付物都有来源、用途、证据等级和下游接手判断。
4. 打开 trace.json，确认故事、资产、图片、提示词和恢复动作不是孤立文件，而是一条可追溯链路。
5. 打开 production-acceptance.json，确认公开样例有没有把“结构演示”和“真实生产质量”混为一谈。
6. 打开模型配置说明，确认每个办公室和部门需要什么类型的模型能力。
7. 打开办公室扩展决策简报，确认后续办公室不是随便复制 UI，而是必须先过隔离、schema、恢复和声明门禁。
8. 最后看线上验证状态：只有 `npm run check:online` 通过后，才能把 `/three-stooges/` 当成正式线上入口发给外部访客。

## 面试时可以这样讲

“这是我做的一个本地优先多 Agent 工作台。公开页面是 no-key demo，它不会暴露我的模型 Key，也不会让访客直接消耗我的额度。这个 demo 重点不是炫模型效果，而是展示我如何把一个复杂任务拆成办公室、Agent 分工、人工审核节点、交付物、追溯文件和发布验收门禁。

目前 AI 漫剧制片办公室是主力样例。它的目标不是直接生成一部视频，而是输出可以交给下游视频工具继续生产的制片画布：人物、道具、场景、提示词、图片记录、Word 文档和 handoff manifest。公开样例只证明结构和交付链路；真实生产质量需要本地配置模型 Key 后，再跑真实模型、图片质检和人工验收。”

## 不能这样讲

- 不能说“面试官可以直接在线生产完整 AI 漫剧”。
- 不能说“这个线上 demo 已经接入我的真实 API Key”。
- 不能说“公开样例证明真实画质已经生产级”。
- 不能说“研究办公室已经能自动登录飞瓜并完成会员级截图采集”。
- 不能把本地通过、GitHub Actions 通过、静态包通过，说成 Vercel 线上入口已经通过。

## 线上 404 时怎么解释

如果个人网站 `/three-stooges/` 仍然是 404，说明 Vercel 还在服务旧部署，或者个人网站项目还没有从当前 GitHub 分支重新部署。

这时可以展示本地或离线评审包，但要明确说明：

- GitHub 仓库和静态包已经准备好。
- 线上公开 URL 还需要 Vercel 重新部署后再验收。
- 只有 `npm run check:online` 通过，才算线上入口可以正式发给外部访客。

## 安全边界

公开展示包禁止包含：

- API Key、Cookie、登录态。
- `config.yaml`、`.env`。
- `user_data/`、`output/`、`runtime_logs/`。
- 浏览器 profile、飞瓜账号信息、真实用户工作区。

公开页面只应该包含固定样例、说明文档、可复核清单、公开截图和 no-key 静态数据。
