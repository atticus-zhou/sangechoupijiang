# 部署模式说明

三个臭皮匠目前是本地优先的多 Agent 协作工作台。公开展示可以上线，但真实生产能力不应该直接暴露给陌生访问者。

## 快速选择

| 使用场景 | 推荐模式 | 可以开放什么 | 必须禁止什么 |
| --- | --- | --- | --- |
| 公开作品集、个人网站、面试展示 | 演示模式 | 产品说明、固定样例、样例 Word、样例引用清单、只读流程状态、只开放 `/api/demo` | 禁用真实生产接口，禁用真实模型调用，禁用写入用户工作区 |
| 自己真实创作、调研、内测 | 本地真实模式 | 使用者在本机填写自己的 Key，运行完整办公室工作流，生成本地 Word、图片和历史记录 | 不提交 `config.yaml`、`.env`、`user_data/`、`output/`、日志、数据库和生成文件 |
| 给陌生访问者在线真实使用 | 未来 SaaS 模式 | 访问者使用自己的 Key，或通过服务端代理调用受控模型额度 | 不要把 Key 放进前端 JavaScript、HTML、静态 JSON 或公开环境变量 |

发布前先运行：

```powershell
python scripts/check_no_secrets.py
python scripts/verify_product_readiness.py --format markdown
```

如果这两个检查没有通过，不要把当前仓库、构建产物或公开页面交给别人使用。

## 演示模式

演示模式用于个人网站、面试展示和公开作品集。

- 只展示固定样例项目、固定流程状态和固定交付物。
- 可以提供样例 Word 画布、引用清单、截图和流程说明下载。
- 不调用真实模型，不读取用户本地配置，也不消耗作者 API Key。
- 不允许访问真实生产接口，不允许提交需要真实模型执行的任务。
- 可以部署到 Vercel、Netlify、GitHub Pages 等静态或半静态环境。

公开页面里可以放 GitHub 链接、产品说明、无 Key 演示入口和样例交付物。不要把个人 API Key 写入前端，也不要把它放入 Vercel 前端环境变量。

## 本地真实模式

本地真实模式用于真正执行研究报告、AI 漫剧制片包和后续办公室任务。

- 使用者自己下载仓库，在本机运行 `python run.py --port 8080`。
- 使用者在 `config.yaml` 或本机环境变量里填写自己的模型 Key。
- `config.yaml`、`.env`、`user_data/`、`output/`、日志和数据库都不提交到 GitHub。
- 工作流可以调用真实模型、写入本地工作区、生成 Word 画布和历史记录。
- 适合个人生产、演示录屏、内测和继续开发。

这个模式的安全边界是：Key 留在使用者自己的机器上，公开仓库只提供代码、样例和说明。

## 未来 SaaS 模式

未来 SaaS 模式是另一个阶段，不等同于把当前本地版直接部署出去。

它至少需要补齐：

- 用户账号、权限和租户隔离。
- 后端密钥托管、额度控制和计费策略。
- 队列系统、任务恢复、并发限制和失败重试。
- 文件存储、下载授权和过期链接。
- 审计日志、模型调用成本记录和安全告警。

在这些能力完成前，公开上线应优先使用演示模式；真实生产应优先使用本地真实模式。
