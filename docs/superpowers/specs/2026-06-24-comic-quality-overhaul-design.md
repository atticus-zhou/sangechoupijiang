# AI 漫剧办公室质量重构设计

## 目标

把 AI 漫剧办公室从“能自动跑完流程”升级为“能稳定交付可生产制片包”。最终质量以《借月人》独立制片画布为参考：故事、视觉母版、基础资产、镜头执行和 Word 交付物属于同一个作品系统，而不是互相松散的文本与图片。

本轮不追求增加更多 Agent，也不重做大厅和侧边栏。核心目标是让现有 Agent 在清晰合同、证据链和质量门下协作。

## 方案比较

### 方案 A：继续修补现有 `workflow.py`

优点是改动快、短期接口变化少。缺点是文件已经同时承担故事、资产提取、提示词、镜头和回退逻辑，并存在重复函数定义；继续叠加会让后定义覆盖前定义，测试通过也难以证明真实运行的是预期实现。

### 方案 B：建立隔离的 V2 制片管线，逐步接管旧流程

这是推荐方案。新模块负责结构化合同和质量决策，旧 API 与 UI 暂时保留，通过适配器读取 V2 结果。每完成一阶段就切换一个能力，失败时可以回到 GitHub 备份分支 `codex/comic-production-hardening`。

### 方案 C：完全重写办公室

边界最干净，但会同时破坏工作区、历史、模型配置、任务事件和现有测试，无法满足“逐步优化、每步可验证”的要求，本轮不采用。

## 总体架构

V2 管线由五个有明确输入输出的模块组成：

1. `creative_contract.py`：把确认故事转成不可随意改写的故事合同和视觉母版。
2. `asset_manifest.py`：从故事合同提取人物、道具、场景，并为每项资产保存原文证据、用途和下游引用。
3. `prompt_director.py`：根据单项资产或单个镜头生成专属提示词，不再依赖一份全局模板批量替换名词。
4. `visual_review.py`：同时比较当前图、资产身份证参考图和视觉母版，检查跨图一致性。
5. `word_canvas_v2.py`：按制片阅读顺序生成页面式 Word，并在交付前执行结构和渲染检查。

旧 `workflow.py` 只保留请求解析和 V1 兼容适配。新逻辑不得继续堆入该文件。

## 阶段一：故事合同与视觉母版

### 故事合同

确认故事后生成 `CreativeContract`，至少包含：

- `story_id`、`story_version`、`source_mode`、`source_hash`
- 原始故事全文，不允许下游 Agent 改写
- 核心命题、人物目标、冲突、因果链、结局
- 分集与场次，每个场次保存故事原文证据
- 用户明确保留和明确禁止的内容

任何资产、镜头和图片都必须带同一个 `story_id` 与 `story_version`。故事版本改变时，旧资产进入 `stale`，不能继续组装交付物。

### 视觉母版

视觉母版 `VisualBible` 至少包含：

- `style_id` 与版本
- 媒介、时代、画面比例、线条、材质、色彩、光线、镜头语言
- 人物、服装、道具和建筑的统一规则
- 项目级视觉母题与色彩叙事
- 项目级禁用元素

视觉母版不是一段形容词，而是可以被提示词生成、视觉质检和 Word 画布共同读取的结构化合同。

### 状态规则

- LLM 结构化输出失败时状态为 `planning_failed`。
- 规则模板只允许生成预览，不允许伪装成正式合同。
- 故事合同和视觉母版均通过用户确认后，才能进入资产拆解。

## 阶段二：资产清单、证据链与人工审核

每项资产保存：

- 稳定 `asset_id`、类型、名称、版本
- 来自故事的原文证据和场次 ID
- 为什么必须存在、在哪些镜头复用
- 视觉锁定项和允许变化项
- 计划生成的图片类型
- 当前审核状态与退回意见

人物默认生成三视图与表情表；道具默认生成白底多角度与基础状态；场景默认生成广角建立图、俯视布局图和常用机位。用户审核页面默认只展示“有哪些人物、道具、场景及其依据”，提示词放入可展开详情，避免审核界面被长文本淹没。

退回必须创建新版本并应用用户意见。新旧版本的清单哈希不同；如果内容没有变化，系统必须明确报错，禁止把旧版重新显示为新版。

## 阶段三：提示词导演与镜头执行卡

提示词分两层：

1. `PromptPlan`：导演意图，包括资产用途、构图目标、连续性锚点、允许变化和失败风险。
2. `GeneratorPrompt`：针对具体模型生成的可执行提示词。

人物、道具、场景基础资产只锁定设定，不讲剧情。镜头执行卡负责叙事，每张卡包含：

- 镜头目的与对应场次
- 首帧参考资产
- 人物动作链和表演意图
- 构图、景别、焦段、机位与运镜
- 灯光、色彩、环境和声音
- 台词与口型策略
- 模型专属提示词
- 镜头特有负面提示词
- 失败后的降级或重试方案

提示词由大模型按单项或小批次生成，刑部在用户审核前检查故事贴合度、资产引用完整度和模型可执行性。失败时展示失败，不静默退回通用模板。

## 阶段四：跨图视觉质检

现有逐图质检升级为引用感知质检。刑部调用视觉模型时至少接收：

- 当前生成图
- 对应资产已经批准的身份证图
- 同角色或同场景上一张合格图
- 视觉母版摘要
- 当前图片的验收标准

质检维度包括：身份一致性、时代与媒介、画风、空间结构、道具形状、基础资产纯净度、明显畸形和用途匹配。每个维度独立评分并给出证据，不能只返回一个总分。

没有参考图时只允许判定“单图质量”，不得声称“一致性通过”。任何必需图片缺失、未质检或跨图一致性未通过，都阻塞 Word 最终交付。

## 阶段五：页面式 Word 制片画布

Word 画布按以下顺序输出：

1. 封面与项目使用说明
2. 完整故事与分集结构
3. 视觉母版
4. 每个角色一页资产身份证
5. 道具资产页
6. 每个场景一页空间资产
7. 场次连续性状态表
8. 每个镜头一页执行卡
9. 下游生产与验收清单

禁止继续使用九列横向大表作为主要交付形式。文档生成后必须执行：DOCX 结构检查、图片引用检查、PDF/PNG 渲染和空白页/溢出检查。渲染失败时交付状态为 `document_review_required`，不能标记完成。

## 人机交互

用户只承担四个不可替代的决策：

1. 确认故事。
2. 确认视觉母版。
3. 确认资产清单。
4. 对自动质检未能解决的图片做最终取舍。

其余拆解、提示词、生成、质检、重试和组装由办公室完成。每次点击后必须立即显示状态变化、当前 Agent、正在处理的对象和下一步，不允许通过切换项目才刷新状态。

## 隔离与兼容

- 所有配置继续以 `office_id=comic_production` 隔离，不影响研究办公室和以后新办公室。
- V2 数据写入独立版本字段和任务目录，不覆盖现有历史产物。
- 旧项目可查看和下载，但只有新创建或明确升级的项目进入 V2。
- GitHub 备份分支 `codex/comic-production-hardening` 是本轮回退基线。

## 分阶段验收

### 验收一：合同

- 完整故事原文在生产过程中一个字不被改写。
- 所有下游对象绑定同一故事版本和视觉母版版本。
- 模型失败时明确阻塞，不生成伪正式合同。

### 验收二：资产

- 资产均能追溯到故事原文；无证据资产不能进入正式清单。
- 退回补充道具后，新版本确实增加道具且旧审核失效。
- 人物、道具、场景默认图片规格符合各自用途。

### 验收三：图片与镜头

- 基础资产不讲故事，镜头卡负责叙事。
- 质检能比较参考图并识别同角色脸型、服装或画风漂移。
- 每张镜头卡引用真实存在且已批准的资产 ID。

### 验收四：交付物

- Word 不使用九列拥挤主表。
- 每个镜头和对应提示词在同一页或同一视觉区块。
- 渲染后无空白页、内容截断和图片错配。

## 非目标

- 不在本轮生成最终视频或替代剪辑平台。
- 不要求用户更换现有 DeepSeek、千问或豆包模型。
- 不重做办公室大厅、通用侧边栏和其他办公室。
- 不同时重写任务引擎、历史系统和模型配置系统。
